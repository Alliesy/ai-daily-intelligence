## 최우선 편집 기준 — 쉬운 말로 설명하기 (사용자 지시 2026-11-27)

- 기본 독자는 AI·개발·전문용어를 모르는 일반인입니다. 쉬운 한국어로 이해되는지는 수집 후 작성·편집·게시의 필수 통과 조건입니다. 단순히 영어를 한글로 옮기는 것으로 통과시키지 않습니다.
- 제목은 제품명·약어·성능 숫자보다 “누가 무엇을 할 수 있게 됐는지, 무엇이 달라졌는지”를 먼저 말합니다. 고유명사가 꼭 필요하면 남기되 그 이름을 몰라도 제목의 뜻이 통해야 합니다.
- 첫 2~3문장에는 ① 무슨 일이 생겼는지 ② 누구의 생활·일·비용·선택에 어떤 차이가 있는지 ③ 지금 쓸 수 있는지와 중요한 제한을 설명합니다. 영향이 확인되지 않으면 모른다고 쓰고 이득을 만들어 붙이지 않습니다.
- AI 에이전트, 추론, API, MCP, RAG, 토큰, 가중치, 배포, 벤치마크 같은 용어는 제목·요약에서 가능한 한 일상말로 바꿉니다. 꼭 필요하면 첫 등장 문장에서 짧게 풉니다. 예: “API” → “다른 프로그램에서 이 AI 기능을 연결해 쓰는 방식”, “벤치마크” → “정해진 문제로 성능을 비교하는 시험”. 용어만 한글로 음역하거나 어려운 말로 다시 설명하지 않습니다.
- 한 문장에는 핵심 하나를 담고, 주어와 행동이 보이는 짧고 자연스러운 문장으로 씁니다. 회사 발표문·번역문·보고서체와 “생태계 확장·워크플로 혁신·추론 최적화” 같은 추상어 나열을 걷어냅니다.
- 쉬운 설명에서도 발표·계획·회사 주장·독립 확인·예상을 구분하고 가격 단위, 한국 제공 여부, 이용 대상, 날짜, 미확인 사항을 보존합니다. 실제 근거 없는 비유·확신·효과나 억지 체험 과제를 덧붙이지 않습니다.
- 코드 식별자·스키마 key·enum·원문 인용·원문 제목·URL은 증거 추적을 위해 유지합니다. 화면에 보여줄 설명은 별도로 쉽게 쓰고, 기존 필드 안에서 처리합니다. 새 필드를 임의로 만들거나 과거 아카이브를 일괄 재작성하지 않습니다.
- 게시 직전 제목과 첫 3문장만 읽는 비전문 독자 관점에서 “무슨 일인가 / 나와 무슨 관계인가 / 지금 가능한 것과 아직 모르는 것은 무엇인가”를 답해 봅니다. 설명되지 않은 용어나 위 질문에 답할 수 없는 문안은 다시 쓴 뒤 재검토합니다. 자동 구조 검증 통과를 이해도 검증 통과로 간주하지 않습니다.
- JSON 표시 필드, 전체 보고서, Latest, Notion, 웹에 전달할 문안, 완료 알림까지 같은 기준을 적용합니다. 웹에서 뒤늦게 임의 요약·번역하지 말고 발행 정본을 만들 때 검토합니다.


## 문안 검토 예시

다음은 표현을 비교하기 위한 예시이며 새 뉴스나 제품 성능 주장이 아닙니다.

| 어려운 표현 | 쉬운 표현 방향 |
|---|---|
| 문서 비전 모델 가중치 공개 | 문서에서 내용을 읽는 AI 파일 공개…직접 내려받아 실행 가능 |
| 에이전트 추론 벤치마크 개선 | 여러 단계 일을 하는 AI, 정해진 시험에서 정답률 상승 |
| API 단가 인하 | 프로그램에 연결해 쓰는 AI 요금 인하…일반 구독료와는 구분 |

예시 문구도 실제 발행 시에는 원문이 뒷받침하는 범위로 고칩니다. 다운로드·실행·구독 여부가 미확인이라면 해당 예시를 그대로 사용하지 않습니다.

## 담당별 책임

- 리서치: 원문 증거와 이용 조건을 확인하고 사실을 일반인이 이해할 문장으로 설명합니다.
- 편집: 제목과 첫 3문장 이해도, 독자 관련성, 과장과 용어 풀이를 검토합니다.
- 게시·개발: 검토된 정본의 문안을 일관되게 전달하고 필드·출처·시점이 유실되지 않는지 확인합니다.

구조 검증은 형식·참조·개수를 확인합니다. 쉬운 말의 품질은 편집 검토로 별도 확인하며 점수를 임의로 만들어 사용자 실험 결과처럼 표시하지 않습니다.
